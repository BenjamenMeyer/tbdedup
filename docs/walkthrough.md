# Thunderbird Deduplicator (`thunderbirddedup`) — User Guide & Walkthrough

`thunderbirddedup` (`tb-dedup` / `tb-dedup-gui`) deduplicates Mozilla Thunderbird MBOX mail files and reconstructs a clean `.sbd` folder hierarchy when folders have been recursively duplicated or contain duplicate messages.

## 1. Before You Begin: Safety Checklist

1. **Close Thunderbird Completely:**
   Ensure Thunderbird is not running before scanning or deduplicating your profile so that neither MBOX files nor `.msf` index files are modified during processing.
2. **Use Separate Working and Output Directories:**
   Always point `--storage-location` (working directory for temporary symlinks and SQLite databases) and `--output-location` (target directory for the reconstructed `.sbd` folder tree) to directories **outside** your live Thunderbird profile. Your original mail directory is only read (never modified in-place).
3. **Check Available Disk Space:**
   Ensure the drive hosting your working directory (`--storage-location`) and output directory (`--output-location`) has enough free space to hold the deduplicated MBOX files plus the temporary SQLite hash databases.

Clone the repository and install into a Python virtual environment (Python 3.12+ recommended):

```bash
git clone https://github.com/BenjamenMeyer/tbdedup
cd tbdedup
```

- `tb-dedup-gui`: Direct launcher for the PySide6 desktop GUI.

## 3. Understanding How `thunderbirddedup` Works

### Folder Discovery
Thunderbird stores local mail folders using two constructs:
- An extensionless MBOX file (e.g., `Inbox`, `Sent`, `change.org`, `Classmates.com`, `104.7_TheFish`) containing the messages in that folder.
- An optional `<FolderName>.sbd/` subdirectory containing child folders.
- A `<FolderName>.msf` Mork/Gloda summary index file generated by Thunderbird.

When scanning a mail directory, `thunderbirddedup` automatically skips non-MBOX files (`.msf`, `.dat`, `.json`, `.sqlite`, `.wdseml`, `.html`, `.mboxrecord`, `.swp`, and hidden dotfiles starting with `.`) while preserving valid MBOX files whose folder names contain dots.

### Pre-Planning (Grouping Recursive Copies)
When a folder hierarchy such as `Inbox` / `Inbox.sbd/` is accidentally copied into a subfolder (for example, `Inbox.sbd/Activities.sbd/Scouts.sbd/Kids.sbd/Inbox.sbd/...` repeated 18–20 levels deep), the preplanner splits paths on the recurring `--folder-pattern` (default `Inbox.sbd/`). All copies of a logical folder across all nesting depths are grouped into a single deduplication plan:

```text
Inbox.sbd/Merchants.sbd/Social.sbd/change.org
Inbox.sbd/Activities.sbd/Scouts.sbd/Kids.sbd/Inbox.sbd/Merchants.sbd/Social.sbd/change.org
Inbox.sbd/Activities.sbd/.../Kids.sbd/Inbox.sbd/Merchants.sbd/Social.sbd/change.org
  --> Grouped into logical plan: Inbox.sbd/Merchants.sbd/Social.sbd/change.org
```

Any recursive copies of the root `Inbox` MBOX file (`.../Kids.sbd/Inbox`) are also grouped with the root `Inbox` plan.

### Message Boundary Detection & Canonical Hashing
Each MBOX file is streamed line-by-line:
- **Boundary Detection:** Matches standard `asctime` and Thunderbird `From - <Day> <Mon> <DD> <HH:MM:SS> <YYYY>` envelope lines, without requiring a preceding blank line and without mistaking body sentences starting with `"From ..."` for message separators.
- **Parsed Hash (`--msg-hash-source parsed`, Default):**
  Computes a canonical SHA-256 over the message headers and body:
  - Normalizes `\r\n` to `\n` and strips trailing blank separator lines.
  - Sorts headers case-insensitively.
  - **Includes `Message-ID`** (an RFC 5322 sender-assigned identifier) so distinct automated messages with identical bodies never collide.
  - **Excludes local bookkeeping headers** (`X-Mozilla-*`, `X-Account-Key`, `X-UIDL`, `X-Folder`, `X-Apparently-To`) and the MBOX `From ` envelope line so copies of the same message with different read/tag states still match.
- **Disk Hash (`disk`):**
  Computes a SHA-256 over the exact raw bytes on disk so that when the winning message is read back via `seek()`/`read()`, its raw byte integrity is verified before writing.

### Merging Thunderbird `X-Mozilla-*` Flags & Tags
When duplicate copies of a message have different flags across folders, `thunderbirddedup` merges their metadata before writing the single deduplicated message:
- **`X-Mozilla-Status` & `X-Mozilla-Status2`:** Bitwise-ORs flags across all duplicate copies so `Read` (`0x0001`), `Replied` (`0x0002`), `Marked/Starred` (`0x0004`), `Forwarded` (`0x1000`), and `Attachment` (`0x10000000`) states are preserved if set on *any* copy.
- **Clears Deletion Flags:** Explicitly unsets `MSG_FLAG_EXPUNGED` (`0x0008` in `X-Mozilla-Status`) and `MSG_FLAG_IMAP_DELETED` (`0x00200000` in `X-Mozilla-Status2`) so kept messages are never hidden by Thunderbird.
- **`X-Mozilla-Keys`:** Merges unique Thunderbird tags/keywords (e.g., `$label1`, `$notjunk`) in order of appearance, padded to at least 80 characters so Thunderbird can add tags in-place later.
- **Synthesizes Missing Headers:** If a message moved from an IMAP folder lacks `X-Mozilla-Status`, `X-Mozilla-Status2`, or `X-Mozilla-Keys`, those headers are inserted right after the `From ` line.

## 4. Walkthrough 1: Interactive Desktop GUI (`tb-dedup gui` / `tb-dedup-gui`)

The PySide6 desktop GUI lets you inspect discovered folder sets, choose whether to deduplicate all folders or only specific subsets, monitor free disk space, and confirm the final reconstruction.

### Step 1: Launch the GUI

```bash
tb-dedup gui
# or:
tb-dedup-gui
```

### Step 2: Configure Paths & Options
At the top of the window, configure:
- **Source Mail Path:** Click **Browse...** and select your Thunderbird mail folder (e.g., `~/.thunderbird/<profile>.default/Mail/Local Folders/Inbox.sbd` or `~/.thunderbird/<profile>.default/Mail/Local Folders`).
- **Working Storage Path:** Select a temporary working directory on a drive with sufficient free space (e.g., `~/tb-dedup-work`).
- **Reconstructed Output Path:** Select where the clean `.sbd` folder hierarchy should be written (e.g., `~/tb-dedup-clean/Inbox.sbd`).
- **Folder Split Pattern:** Leave as `Inbox.sbd/` (default) unless your recursive duplication occurred on a different folder name.
- **Limit Regex (Optional):** Optionally filter discovered files by a regular expression.
- **Hash Source:** Leave on `parsed` (recommended) so copies with different `X-Mozilla-Status` flags deduplicate together.

Notice the **Storage Free Space** indicator in the status area—it monitors available disk space on your working storage drive every 2 seconds.

### Step 3: Scan & Pre-Plan
1. Click **1. Scan & Pre-Plan**.
2. The tool walks the Source Mail Path asynchronously and populates two tabs in the center pane:
   - **Folder Hierarchy (TreeView):** Shows the reconstructed folder hierarchy with checkboxes, the number of duplicate MBOX files found for each folder, and total source size. Checking or unchecking a parent folder automatically checks/unchecks its children.
   - **Logical Plans (ListView):** Shows a flat checkable list of all logical folder plans for quick bulk selection (**Select All** / **Deselect All**).
3. Click any folder in the tree or list to inspect its underlying source MBOX file paths and per-file sizes in the **Plan Details & Summary** panel on the right.

### Step 4: Deduplicate Selected Folders
1. Keep all folders checked for a full recovery, or check only specific folders you want to process right now.
2. Click **2. Deduplicate Selected**.
3. The progress bar and **Live Log Output** panel track each folder plan as messages are indexed into SQLite, deduplicated, and verified.
4. When deduplication finishes, the **Plan Details & Summary** panel displays the full **Thunderbird Deduplication Summary** report showing:
   - Total MBOX files and logical folders processed
   - Total messages indexed vs. unique messages kept (and duplicates removed)
   - Original MBOX size vs. deduplicated MBOX size (and disk space saved)

### Step 5: Confirm & Move to Target
1. Review the summary report in the right-hand panel.
2. Click **3. Confirm & Move to Target** and confirm the dialog prompt.
3. The deduplicated MBOX files are moved into your **Reconstructed Output Path** in a clean `.sbd` folder hierarchy (with no stale `.msf` files), and the temporary working directory is cleaned up.

## 5. Walkthrough 2: End-to-End Automated CLI Reconstruction (`tb-dedup do`)

If you prefer running the entire workflow from the terminal, use `tb-dedup do`.

### Step 1: Create Working and Output Directories

```bash
mkdir -p ~/tb-dedup-work ~/tb-dedup-clean/Inbox.sbd
```

### Step 2: Run `tb-dedup do`

```bash
tb-dedup do \
    --location ~/.thunderbird/<profile>.default/Mail/Local\ Folders/Inbox.sbd \
    --storage-location ~/tb-dedup-work \
    --output-location ~/tb-dedup-clean/Inbox.sbd
```

### Step 3: Review the Summary Report and Confirm
Once all folder plans finish deduplicating in `~/tb-dedup-work`, `tb-dedup do` prints a summary report and asks for confirmation before moving the reconstructed MBOX files into `~/tb-dedup-clean/Inbox.sbd`:

```text
========================================================================
Thunderbird Deduplication Summary
========================================================================
Source Location:        /home/user/.thunderbird/profile/Mail/Local Folders/Inbox.sbd
Working Directory:      /home/user/tb-dedup-work/20261027_220000thunderbirddedup
Reconstructed Target:   /home/user/tb-dedup-clean/Inbox.sbd
Source MBOX Files:      6503
Logical Folders (Plans): 799 (799 succeeded, 0 failed)
Messages Indexed:       8823279
Unique Messages Kept:   512410 (8310869 duplicates removed)
Original MBOX Size:     330.15 GB (354495811584 bytes)
Deduplicated MBOX Size: 3.12 GB (3350074490 bytes)
Disk Space Saved:       327.03 GB (99.05%)
========================================================================
Proceed with moving 799 deduplicated MBOX files to '/home/user/tb-dedup-clean/Inbox.sbd'? [y/N]:
```

- Type `y` and press **Enter** to move the deduplicated MBOX files into `~/tb-dedup-clean/Inbox.sbd` and remove the temporary working directory.
- Type `n` (or press **Enter**) to leave the deduplicated files inside the working directory for manual inspection without moving them.
- Pass `--yes` (`-y`) on the command line if running non-interactively (e.g., in an overnight script) to auto-confirm the move.

## 6. Walkthrough 3: Step-by-Step CLI Pipeline (`preplanner`, `planner`, `dedup`)

For fine-grained debugging or single-folder deduplication, you can run each phase individually.

### Phase A: `preplanner` (Inspect Folder Grouping Only)
Scans `--location`, groups MBOX files by `--folder-pattern`, and writes a timestamped `*_preplan.json` file in the current directory without deduplicating anything:

```bash
tb-dedup preplanner \
    --location ~/.thunderbird/<profile>.default/Mail/Local\ Folders/Inbox.sbd \
    --folder-pattern "Inbox.sbd/"
```

### Phase B: `planner` (Create a Symlink Workspace for Matching Folders)
Searches `--location` (optionally filtered by `--limit-pattern`), creates a timestamped directory containing numbered `.mbox` symlinks (`000001.mbox`, `000002.mbox`, ...) and a `mapping.json` file recording their source paths:

```bash
tb-dedup planner \
    --location ~/.thunderbird/<profile>.default/Mail/Local\ Folders \
    --limit-pattern ".*Merchants\.sbd/Social\.sbd/change\.org$"
```

### Phase C: `dedup` (Deduplicate a Single Directory of MBOX Files)
Reads all MBOX files (or planner symlinks) in `--location`, indexes them into `--hash-storage`, and writes a single `*_deduplicated.mbox` file in the current directory:

```bash
tb-dedup dedup \
    --location ./20261027_221500 \
    --hash-storage ./change_org_hashes.sqlite
```

## 7. Restoring the Reconstructed Folder Tree into Thunderbird

Once your clean `.sbd` folder hierarchy has been written to `--output-location` (e.g., `~/tb-dedup-clean/Inbox.sbd`):

1. **Ensure Thunderbird is closed.**
2. **Move your original inflated folder tree to a backup location** (or rename it if you have disk space):
   ```bash
   cd ~/.thunderbird/<profile>.default/Mail/Local\ Folders
   mv Inbox.sbd ~/tb-backup-Original-Inbox.sbd
   rm -f Inbox.msf
   ```
   *(If `~/tb-dedup-clean/Inbox` was also generated from recursive `Kids.sbd/Inbox` copies, back up `Inbox` as well and copy the deduplicated `Inbox` into `Local Folders/Inbox`.)*
3. **Copy or move the reconstructed `Inbox.sbd` into `Mail/Local Folders/`:**
   ```bash
   mv ~/tb-dedup-clean/Inbox.sbd ~/.thunderbird/<profile>.default/Mail/Local\ Folders/Inbox.sbd
   ```
4. **Start Thunderbird:**
   Thunderbird will automatically detect the clean MBOX files and build fresh `.msf` summary index files for each folder using the merged `X-Mozilla-Status`, `X-Mozilla-Status2`, and `X-Mozilla-Keys` headers.
5. **Verify your folders in Thunderbird** before deleting `~/tb-backup-Original-Inbox.sbd`.

## 8. Command-Line Reference

### Global Options
| Flag | Description |
| :--- | :--- |
| `--log-config <file>` | Optional Python `logging.config` file path (defaults to stdout + `.tb-dedup.log`). |
| `-h`, `--help` | Show help message and exit. |

### `tb-dedup gui` (or `tb-dedup-gui`)
Launches the PySide6 desktop GUI application.

### `tb-dedup do`
Runs the full preplan $\rightarrow$ plan $\rightarrow$ parallel deduplication $\rightarrow$ summary confirmation $\rightarrow$ clean `.sbd` folder reconstruction pipeline.

| Flag | Required | Default | Description |
| :--- | :---: | :---: | :--- |
| `--location`, `-l` | Yes | — | Root directory to scan for Thunderbird MBOX files. |
| `--storage-location`, `-sl` | No | System temp dir | Working directory for temporary plan symlinks and SQLite databases. |
| `--output-location`, `-ol` | No | `deduped_mbox` in working dir | Target directory for the reconstructed `.sbd` folder tree. |
| `--folder-pattern`, `-fp` | No | `Inbox.sbd/` | Folder pattern used to split and group recursive folder copies. |
| `--limit-pattern`, `-lp` | No | `None` | Optional regex to filter which MBOX file paths are included. |
| `--msg-hash-source` | No | `parsed` | Hash mode for deduplication (`parsed` or `disk`). |
| `--yes`, `-y` | No | `False` | Auto-confirm moving deduplicated MBOX files to `--output-location`. |

### `tb-dedup preplanner`
| Flag | Required | Default | Description |
| :--- | :---: | :---: | :--- |
| `--location`, `-l` | Yes | — | Root directory to scan for Thunderbird MBOX files. |
| `--folder-pattern`, `-fp` | No | `Inbox.sbd/` | Folder pattern used to split and group recursive folder copies. |

### `tb-dedup planner`
| Flag | Required | Default | Description |
| :--- | :---: | :---: | :--- |
| `--location`, `-l` | Yes | — | Root directory to scan for Thunderbird MBOX files. |
| `--limit-pattern`, `-lp` | No | `None` | Optional regex to filter which MBOX file paths are symlinked. |

### `tb-dedup dedup`
| Flag | Required | Default | Description |
| :--- | :---: | :---: | :--- |
| `--location`, `-l` | Yes | — | Directory containing MBOX files (or planner symlinks) to deduplicate. |
| `--hash-storage`, `-hs` | No | `:memory:` | SQLite database file path for storing message hashes. |
| `--msg-hash-source` | No | `parsed` | Hash mode for deduplication (`parsed` or `disk`). |
